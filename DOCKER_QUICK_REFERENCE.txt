DÉPLOIEMENT RAPIDE (60 minutes)
================================================================================

CENTRAL SERVER:
  1. mkdir -p /opt/prometheus-stack && cd /opt/prometheus-stack
  2. scp docker-compose.yml prometheus.yml alertmanager.yml .
  3. docker-compose up -d
  4. Vérifier: http://localhost:9090/targets

AIRFLOW SERVERS (4×):
  1. bash install_exporters_airflow.sh
  2. Vérifier: curl http://localhost:9100/metrics

GRAFANA:
  1. http://localhost:3000 (admin/admin_change_me)
  2. Change password
  3. Import dashboards (IDs: 12632, 9628, 11835, 1860)

================================================================================
COMMANDES ESSENTIELLES
================================================================================

DÉMARRER/ARRÊTER:
  docker-compose up -d        # Démarrer en background
  docker-compose down         # Arrêter
  docker-compose restart      # Redémarrer
  docker-compose ps           # Status

LOGS:
  docker-compose logs -f              # Tous les logs
  docker-compose logs -f prometheus   # Logs d'un service
  docker-compose logs --tail 50 <svc> # 50 dernières lignes

VÉRIFIER:
  curl -s http://localhost:9090/-/healthy          # Prometheus
  curl -s http://localhost:9093/-/healthy          # AlertManager
  curl -s http://localhost:3000/api/health         # Grafana
  docker-compose ps                                # Status des containers

RECHARGER CONFIG (sans redémarrer):
  curl -X POST http://localhost:9090/-/reload      # Prometheus
  # AlertManager: docker-compose restart alertmanager

EXÉCUTER COMMANDES DANS CONTAINER:
  docker-compose exec prometheus promtool check config /etc/prometheus/prometheus.yml
  docker-compose exec alertmanager amtool check-config /etc/alertmanager/alertmanager.yml
  docker-compose exec grafana grafana-cli admin reset-admin-password <pwd>

================================================================================
TROUBLESHOOTING RAPIDE
================================================================================

Les containers ne démarrent pas:
  → docker-compose logs
  → Vérifier les ports disponibles: netstat -tlnp
  → Vérifier la syntaxe YAML: docker run --rm -v $(pwd):/w prom/prometheus:v2.52.0 promtool check config /w/prometheus.yml

Targets DOWN dans Prometheus:
  → Sur le serveur Airflow: curl http://localhost:9100/metrics
  → Vérifier le service: systemctl status node_exporter
  → Vérifier le port: netstat -tlnp | grep 9100

Emails non reçus:
  → docker-compose exec alertmanager amtool check-config /etc/alertmanager/alertmanager.yml
  → docker-compose logs postfix
  → Tester: curl -X POST http://localhost:9093/api/v1/alerts ...

Grafana - Datasource not working:
  → docker-compose exec grafana ping prometheus
  → curl -s http://prometheus:9090/-/healthy

VOLUMES PERSISTANTS
================================================================================

Données sauvegardées automatiquement dans des volumes Docker:

  prometheus-data
    └─ /prometheus (TSDB)

  grafana-data
    └─ /var/lib/grafana (dashboards, datasources)

  alertmanager-data
    └─ /alertmanager (état des alertes)

Ces volumes survivent aux redémarrages.

Lister les volumes:
  docker volume ls | grep prometheus

Nettoyer (attention - supprime les données!):
  docker volume rm prometheus-data grafana-data alertmanager-data

================================================================================
BACKUP MANUEL
================================================================================

Configurations:
  tar czf backup-config-$(date +%Y%m%d).tar.gz \
    prometheus.yml alertmanager.yml grafana-datasources.yml rules/

Données Prometheus:
  docker run --rm -v prometheus-data:/data -v $(pwd)/backups:/backup \
    alpine tar czf /backup/prometheus-$(date +%Y%m%d).tar.gz -C /data .

Données Grafana:
  docker run --rm -v grafana-data:/data -v $(pwd)/backups:/backup \
    alpine tar czf /backup/grafana-$(date +%Y%m%d).tar.gz -C /data .
